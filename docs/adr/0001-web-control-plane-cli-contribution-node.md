# 0001: 网页作为控制面，CLI 作为贡献节点

- Status: Accepted
- Date: 2026-09-14

> Update: ADR-0004 已取代本文中由 Next.js Route Handler 实现 Control Plane 的技术选择；网页与 Contribution Node 的职责边界仍然有效。

具体任务传输和运行拓扑由 [持久 relay 决策](0003-persistent-relay-and-five-concurrent-requests.md) 细化：Go relay 负责数据转发，Next.js 负责控制与准入，每节点固定 5 并发。

## Context

clovapi 需要同时服务两类行为：Consumer 创建凭证、查看额度并选择路由；Contributor 保存上游凭据、长期在线并执行共享请求。若全部放在网页端，贡献者必须把上游密钥交给平台后端，或长期保持浏览器页面运行。后者还受 CORS、页面休眠和后台执行限制。

当前 clovapi CLI 已具备本地配置、协议转换和请求代理能力，适合演进为受贡献者控制的常驻执行组件。

## Decision

网页与平台后端组成 Control Plane，负责账户、平台凭证、路由策略、贡献开关、任务派发和积分账本。Consumer 直接使用网页和平台 API，不要求安装 CLI。

CLI 保留，并收敛为 Contribution Node 的首个运行形态。它保存上游凭据，使用节点身份主动建立出站连接，从 Control Plane 领取任务，按本地预算与自用保留规则执行，并上报用量。网页只保存贡献规则和节点状态，不接收上游密钥。

Contribution Node 对应一个 CLI 实例，包含该实例自动发现的全部可用本地模型。用户在控制台复制包含账户连接密钥的 `clovapi share start --key ...` 命令；CLI 从密钥识别平台并注册实例，Control Plane 自动创建或恢复账户节点，CLI 保存独立节点凭证。网页生成命令不会预先创建节点，也不提供手动创建单模型节点的入口；共享命令不要求选择 profile、模型或平台地址。模型清单随后自动同步，平台只接收模型 ID，不接收上游地址或密钥。

账户连接密钥可以连接多个实例，轮换或撤销只影响后续注册。已接入实例使用各自的节点凭证继续运行，用户通过网页断开具体节点来撤销其运行权限。

Control Plane 使用 Next.js Route Handler 实现邮箱验证码、服务端会话、按账户隔离的数据和凭证管理。当前持久化使用 SQLite；当部署拓扑需要多实例写入时迁移到支持共享事务的数据库。

## Consequences

- 普通 API 使用者的接入路径更短，平台 UI 可以独立迭代。
- 贡献者的上游密钥留在其设备或基础设施内，贡献节点可作为服务、容器或桌面包装长期运行。
- 账户授权以 CLI 实例为单位，新增或移除本地可用模型无需重复创建节点。网页负责查看模型与在线状态、暂停、每日请求上限和断开连接；节点内所有模型共享并发与每日请求限制。
- CLI 需要新增节点认证、出站任务通道、预算执行、暂停、重连和用量证明；当前本地代理不能直接视为公网共享节点。
- Control Plane 仍会接触社区请求内容并负责派发，需要明确数据路径、最小化日志并建立节点信任和审计机制。
- 生产阶段可替换 SQLite，但应保持 Control Plane 与 Contribution Node 的职责边界。

## Alternatives Considered

- **仅网页后端**：开发入口简单，但要求托管贡献者密钥，扩大密钥保管责任。
- **浏览器作为贡献节点**：密钥可留在浏览器，但后台可靠性、CORS 和持续在线能力不足。
- **所有用户都使用 CLI**：复用现有核心，但提高 Consumer 首次调用门槛，不利于免费 API 的获客目标。
