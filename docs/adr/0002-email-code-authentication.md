# 0002: 使用邮箱验证码和服务端会话登录控制台

- Status: Accepted
- Date: 2026-09-14

## Context

clovapi 面向首次尝试 API 的开发者，需要低门槛登录，同时要支持网页 Control Plane 中的用户隔离。密码会引入找回、强度和泄漏处理；社交登录会立即依赖特定身份提供商。

## Decision

控制台使用邮箱加六位一次性验证码。验证码十分钟过期，同一邮箱一分钟内不能重复发送，每个验证码最多尝试五次；数据库只保存由服务端密钥生成的验证码哈希。

验证成功后创建三十天有效的随机会话令牌。浏览器只接收 HttpOnly、SameSite=Lax Cookie，数据库只保存令牌哈希。登录会撤销该用户已有会话，退出登录会同时撤销服务端会话和 Cookie。

邮件始终通过 Resend API 发送。所有环境都必须配置 `AUTH_SECRET`、`RESEND_API_KEY` 和 `RESEND_FROM`；缺少配置时拒绝发送，不打印或回传验证码。发送请求使用验证码记录 ID 作为幂等键，避免网络重试产生重复邮件。

## Consequences

- 用户无需设置和找回密码，调用凭证、贡献节点与账本直接归属于账户。
- 邮箱服务的可用性影响登录，需要监控发送失败和配置退避策略。
- 上线前还需增加 IP 与设备维度的限流、邮件退信处理、会话管理界面和异常登录审计。
- 当组织账户和团队成员体系出现时，邮箱用户作为个人身份继续存在，组织授权单独建模。

## Alternatives Considered

- **密码登录**：不依赖邮件即时送达，但增加密码存储、找回和撞库防护成本。
- **OAuth 登录**：体验成熟，但早期需要选择并维护第三方身份提供商。
- **浏览器本地身份**：实现简单，无法形成跨设备账户，也不能安全隔离平台账本。
