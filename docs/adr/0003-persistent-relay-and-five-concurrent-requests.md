# 使用持久反向连接转发共享调用

> Update: ADR-0004 已取代本文中独立 Relay 回调 Next.js Control Plane 的部署方式；持久反向连接、流控和每节点 5 并发的决定仍然有效。

共享模型调用需要即时派发和连续流式输出。采用独立 Go Relay 接受消费者 API，通过贡献节点主动建立的 WebSocket 长连接实时派发请求；所有模型共用节点的 5 个执行槽位。Next.js Control Plane 保留账户、权限、原子限额准入和终态元数据，SQLite 不再承担请求正文与响应块的队列。

这个选择保留上游凭据在本地，并消除短轮询等待和每个响应块的数据库读写。未选择长轮询过渡方案，也未采用平台托管上游密钥。节点不要求公网入口，贡献者仍使用网页提供的同一条启动命令。

每个请求具有独立的流控窗口、取消信号和超时；连接中断取消在途调用，重连仅接受新请求，不自动重放可能已收费的调用。平台与 CLI 分别检查每日请求数和并发，平台准入在事务内计数，CLI 在执行前持久化本地尝试记录。

当前部署由一个 Relay 持有连接，反向代理网页到内部 Next.js 端口；启动器与容器统一管理两个进程。横向扩展需要明确连接归属和跨 Relay 路由，不能直接把多个互不知情的 Relay 放在随机负载均衡后。升级要求平台和 CLI 同时使用长连接协议，旧任务领取接口返回升级提示。
