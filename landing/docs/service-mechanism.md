# clovapi 服务机制设计

状态：生产机制设计。当前开发版本已实现账户、邮箱验证、API Key 管理和 CLI 共享调用测试版；免费额度发放、积分结算及下文标记的目标机制仍待实现。

## 1. 定位与目标

clovapi 为开发者提供免费或低价的大模型 API，并让有权共享余留额度的个人或团队贡献资源、获得调用积分。平台运营方提供自有或采购的算力，承担基础供给与符合条件的回退请求。这里的“官方”指 clovapi 运营方，不代表模型原厂授权或背书。

平台投入算力的主要目标是让目标开发者完成接入、持续使用，并进一步认识运营方的核心产品。共享机制用于扩展模型供给和提高参与度；贡献不是使用免费服务的前置条件。

## 2. 用户旅程

| 阶段 | 用户行为 | 平台应提供的结果 |
| --- | --- | --- |
| 了解 | 查看可用模型和接入方式 | 展示真实供给、能力、使用额度与积分规则；未开放的能力明确标注 |
| 首次使用 | 创建账户、获得平台调用凭证 | 领取基础免费额度；默认使用官方资源；完成一次可验证的调用 |
| 持续使用 | 查看用量，选择调用模式 | 看到来源、实际消耗、余额与限制；按需选择社区或自动模式 |
| 开始贡献 | 验证可共享资源，设置规则 | 验证模型能力与授权信息；先确认共享上限和开放时间，再接收任务 |
| 获得回报 | 完成其他用户的真实调用 | 调用结算后获得贡献积分；查看逐笔依据和后续兑换范围 |
| 深入了解 | 阅读开发案例、用量报告或控制台推荐 | 自愿进入运营方核心产品；API 响应不夹带广告或推广内容 |

首次成功调用后的示例项目和排错文档应优先于复杂的积分运营。核心产品尚未指定，页面不编造后续转化目的地。

## 3. 两类权益，三个调用模式

### 免费额度与贡献积分

- **基础免费额度**由平台补贴提供，无需贡献即可领取。可用模型、发放周期、速率和总量以账户页面公布的规则为准；不承诺无限免费。
- **贡献积分**是完成共享调用后的平台使用权益。贡献者可以将其用于公布的模型与模式；不承诺提现、固定现金兑换价值或无限期兑付。
- 控制台分别展示两类权益、适用范围与到期规则。调用前展示预计消耗、扣减顺序和价格上限，完成后展示实际消耗。
- 免费额度是否可以消费社区资源，应在上线规则中明确。若允许，产生的贡献奖励计入平台补贴预算，并排除自调自刷及关联账户循环调用。
- 接入 API、申报余额、在线时长、健康检查和平台测试请求均不自动产生贡献积分。

### 调用模式

| 模式 | 路由规则 | 用户应知道的限制 |
| --- | --- | --- |
| 官方 | 只使用 clovapi 运营方提供的资源 | 提供平台标明的模型和能力；仍受额度、限流和实际可用性约束 |
| 社区 | 只使用已通过验证且当前允许共享的资源 | 价格与可用性以当前展示为准；无可用节点时等待或返回明确错误 |
| 自动 | 经用户选择后，优先匹配社区资源，符合条件时回退到官方资源 | 回退需同模型、同能力并满足预算；没有合格官方资源时不能承诺兜底 |

同模型至少包括公布的模型标识和必要版本约束；同能力包括上下文范围、工具调用、结构化输出、多模态和协议要求。平台不得以其他模型冒充用户请求的模型。可接受的替代模型必须由用户单独配置。

自动模式由用户设置单次最高积分消耗或价格上限，并在派发前校验。官方路径超过上限时停止回退并返回可解释结果，不静默提高费用。请求开始输出后，不把另一路结果拼接到原输出。

## 4. 贡献与结算

### 贡献者控制权

- 贡献者授权一个 CLI 实例接入，节点自动同步本地配置中的可用模型。当前可在网页暂停或恢复共享、修改节点每日请求上限、断开节点；时间窗口、可调并发、累计消耗上限及自用保留量仍是待实现的目标能力。
- 本地自用优先。平台派发前预留预算与并发，结束后释放；余额读取不可靠时，以保守预算和实际累计用量控制共享。
- 暂停默认阻止新任务，已开始的请求按既定规则完成。紧急停止可中断执行，并适用相同的中断结算规则。
- 同一个上游账户如果还在平台外使用，平台无法仅凭自身记录保证其剩余额度；不向贡献者宣传绝对不会影响自用。
- 企业或团队资源由有权授权的主体接入，贡献奖励归属对应团队账户。员工个人获得访问权限，不自动视为拥有共享授权。

### 计价与积分账本

调用派发前锁定计价规则与奖励规则，明确模型、来源、输入与输出计量、缓存等适用项。实际消耗按经过核验的已交付用量结算；预估金额仅用于预算预留。

每次逻辑请求拥有唯一标识，各次上游尝试分别记录。消费者最终扣减、贡献者奖励和预留释放在一次可追踪的结算中完成；重复回调和重试不能重复扣减或发奖。奖励在请求确认结算后产生，异常请求进入待核对状态。

模型价格、贡献奖励和补贴比例可以随供需调整，但只影响新请求。调价不追溯已接受的请求；控制台保留当时的规则版本和账单说明。

### 失败、流式与退款

| 情况 | 拟定处理原则 |
| --- | --- |
| 派发前失败或没有可用资源 | 释放预留额度，不扣分、不发奖 |
| 首个有效输出前失败 | 可按路由策略重试；用户只结算最终实际交付，不承担平台内部失败尝试的重复扣费 |
| 已开始流式输出 | 保持当前响应来源，不拼接其他来源的输出；中断时明确标记部分完成，根据可核验的交付用量结算，释放未使用预留 |
| 用量缺失或有争议 | 暂缓相关扣减和奖励，不以未经核验的预估量直接结算；按事先公布的核对时限与退款政策处理 |
| 核对后确认多扣 | 以补偿流水退还原类别权益；涉及贡献奖励时同步纠正账目，保留原因和审计记录 |
| 用户主动取消 | 停止后续生成，按可核验的已交付部分结算；不把取消作为绕过已产生消费的方式 |

流式交付用量的测量方法、缓存和推理 token 等不可直接观察用量的处理，须在实现计量链路后公布。未完成这些能力前，不宣传精确逐 token 计费或无条件失败退款。

## 5. 授权、隐私与服务边界

接入时要求贡献主体确认资源属于其有权共享的范围，并验证上游服务规则是否适用于该接入方式。额度即将过期、已报销或来自企业套餐，都不能单独证明可对外共享。

采用本地连接器方案时，原始上游密钥留在贡献者设备，由连接器执行请求；消费者使用平台凭证，不能取得贡献者密钥。用户在控制台复制 `clovapi share start --key ...` 连接命令，CLI 自动识别平台并注册实例，平台创建或恢复账户节点，向 CLI 发放独立节点凭证。该凭证保存在本地，用于建立到 Platform Worker 的出站 WebSocket 长连接；连接由该节点专属的 NodeSession Durable Object 持有，实时接收请求并逐块交付响应。断开节点会撤销凭证。账户连接密钥保持固定，可以连接多个实例，网页通过断开具体节点管理运行权限。模型清单自动同步，只上传模型 ID，不上传上游地址或 API 密钥。共享进程不开放本地监听端口。

选择社区资源意味着请求内容可能被贡献节点及其上游处理。平台应在首次启用前清楚说明数据路径，提供官方模式及来源记录；不得宣称密钥本地保存就等于提示词对贡献者不可见。敏感项目可固定官方模式，但官方模式仍需公布运营方及实际处理方的数据规则。

默认只记录结算和排错所需的最少元数据。内容日志、保存期限和第三方处理方应在真实实现后披露；“零留存”“完全匿名”“数据不离开本机”等说法须有相应技术与运营依据。

## 6. Landing 应承诺什么

页面主张：**免费开始调用，让用不完的 API 继续产生价值。** 用官方供给建立基础体验，用社区共享补充模型与额度，用积分回馈真实贡献。

推荐信息顺序：免费调用的价值 → 官方与社区如何协作 → 贡献后如何获益 → 三种模式与控制权 → 常见问题 → 与当前状态一致的行动入口。

只展示已经实现或已有明确交付边界的能力。不要展示虚构的用户量、实时节点数、节省金额、固定免费额度、模型清单、延迟、可用性承诺或云 API 地址。尚未接通的服务只说明当前状态和交付边界。

上线前还需决定：

| 待定参数 | 决策依据 |
| --- | --- |
| 免费额度、周期与适用模型 | 可供给算力、目标开发者的正常使用量、滥用控制 |
| 积分价格、贡献奖励与有效期 | 实际计量成本、供需、平台补贴预算与用户预期 |
| 首批模型及官方回退覆盖 | 已验证的模型身份、协议能力与实际容量 |
| 贡献门槛和节点准入 | 主体授权、模型真实性、错误率与预算执行能力 |
| 结算与退款时限 | 真实计量链路、上游用量回传和客服处理能力 |
| 数据保留与处理方披露 | 实际数据路径、日志实现及运营政策 |
| 进一步介绍的核心产品 | 用户希望吸引的开发者群体及可验证的转化入口 |

## 7. 首轮验证与交付边界

先上线官方资源的免费接入与用量可见性，再以邀请制开放少量经授权的共享资源，验证积分结算，最后开放自动模式。各阶段分别验收，Landing 只开放已经完成的入口。

衡量目标以首次成功调用率、首次调用所需时间、持续活跃与真实项目接入为主；随后观察贡献者留存、贡献积分使用率、模型覆盖增量，以及进入核心产品后的有效转化。总请求数和接入密钥数不能单独代表获客成功。

当前版本提供 Landing、邮箱验证码认证、服务端会话、账户级调用凭证、CLI 连接命令、贡献节点和共享调用链路。一个节点对应一个 CLI 实例；用户复制网页命令并在本地运行后，由平台自动创建或恢复节点，随后自动同步本地可用模型，无需浏览器二次确认、网页创建节点或逐个指定模型。平台支持精确模型匹配、长连接即时派发、流式转发、取消和撤销。平台与 CLI 按 UTC 每日请求数执行限制，一个节点的所有模型共用每日请求上限，并发合计为 5。请求数限制不等于 token 或费用预算；本地空闲判断、共享时段、自用优先、官方回退、计量结算和免费额度发放仍需继续建设。本版不扣减额度或生成积分，详细使用方式见 [CLI 共享节点](../../docs/cli-sharing.md)。

## 8. 网页与 CLI 的分工

Consumer 在网页创建账户和平台凭证、查看两类权益、配置调用模式并阅读逐笔账本；调用 clovapi 平台 API 不要求安装 CLI。静态 Web App 只负责界面，Platform Worker 的 Control Plane 拥有账户授权、贡献规则、目录投影和结算规则。D1 保存全局可查询记录；NodeSession Durable Object 负责已连接节点的即时派发和响应转发；AccountGate Durable Object 负责账户级在途请求上限。

CLI 是 Contributor 使用的 Contribution Node，一个实例承载其本地配置中可用的多个模型。它在贡献者设备或服务器上保存上游配置与凭据，自动同步可用模型 ID，通过主动建立的 WebSocket 长连接接收共享请求，并执行每日请求上限、5 并发和暂停规则。每个请求独立流控与取消；断线取消在途调用，自动重连后只接收新请求。Control Plane 负责账户授权、节点身份、贡献规则和状态，不接收上游地址或密钥。网页管理已授权节点的模型与在线状态、暂停、请求上限和断开连接。未来的桌面端、容器和系统服务应复用同一节点核心，而不是复制另一套执行逻辑。

当前 Cloudflare Platform Worker 通过 D1 实现邮箱验证码、服务端会话、按账户隔离的数据、仅存哈希的 API Key 与节点密钥、贡献规则及调用元数据。一个贡献节点映射到一个 NodeSession Durable Object；请求正文与响应块只经过 Worker、NodeSession 和 CLI 的流式通道，不写入 D1 或 Durable Object 存储。Next.js 静态导出只提供网页、文档和控制台界面，通过 `api.clovapi.com` 请求 Platform Worker。验证码由 Platform Worker 通过 Resend API 发送。积分账本保留独立的数据结构，待可核验计量和结算接通后启用。
